# Product Design

## 목적

민표가 “학습 문제를 풀었다”보다 “숫자 보스의 약점을 발견했다”고 느끼는 5~10분 수직 전투 데모를 만든다. 1순위 지표는 진도나 정답률이 아니라 자발적 시작과 부정 감정 감소다.

## 핵심 사용자 흐름

```text
보호자 설정 → 모험 지도 → 숫자 숲 → 직접 조작 → 공격 → 심화 작전
→ 1인/합동 필살기 → 보상 → 생각 보관 → 보호자 요약
```

## 아이 경험 원칙

- 문제집 외피가 아니라 조작 자체가 전투 행동이 된다.
- 아이 화면에는 `공부`, `숙제`, `시험`, `오답`, `실패`, `틀렸다`, 점수 비교를 쓰지 않는다.
- 첫 어려움은 공격이 막힌 것으로, 두 번째 어려움은 보호막과 동료 도움으로 표현한다.
- 정답 외에 조작, 힌트 요청, 설명, 재도전, 협력도 보상한다.
- 주요 입력은 44px 이상이며 360px 세로 화면에서 가로 스크롤이 없어야 한다.
- 효과음과 화면 움직임을 줄이거나 끌 수 있다. 빠른 깜빡임을 사용하지 않는다.

## 2인 협동 원칙

- 같은 기기에서 민표와 친구가 차례로 자기 역할을 수행한다.
- 난이도·학년·정답 수는 서로에게 표시하지 않는다.
- 한 아이가 대신 답을 누르기보다 그림 힌트, 단계 나누기, 응원을 보낸다.
- 두 개인 게이지와 팀 링크가 모두 필요하므로 한 아이가 전투를 독점할 수 없다.
- 팀 보상은 참여 기준으로 같게 지급한다.

## 제외 범위

온라인 서버, Supabase, 계정, 결제, 광고, 외부 AI API, PvP, 랜덤 매칭, 공개 랭킹, 공개 프로필, 자유 채팅, 음성 채팅, 위치 공유는 MVP에서 제외한다.

## 성공 기준

- 1인과 2인 흐름이 모두 처음부터 결과 저장까지 완료된다.
- 새로고침 후 설정, 보상, 협동 기록, 생각 기록이 유지된다.
- 전투에서 `10 만들기 → 8+7=15 → 두 풀이 방법`이 연결된다.
- 2인 모드에서 두 준비 입력 없이는 합동 필살기가 발동하지 않는다.
